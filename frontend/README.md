# Frontend — live catalog and request form (MVP-012/013)

React + TypeScript + Vite: каталог, подробная карточка и общий список выбранных
товаров/услуг. `App` использует `httpCatalog`: реальные same-origin GET через
Nginx → FastAPI → PostgreSQL. При ошибке API показывается ошибка с повтором;
подмены fixtures нет. «Оформить заявку» открывает живую форму с обзором,
согласием и реальным POST orders; ответ показывает безопасный receipt.

## Запуск и проверки

Требуются Node.js **24.19.0** (`.nvmrc`) и npm **11.9.0**. Из `frontend/`:

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
npm run preview
```

Dev: <http://127.0.0.1:5173>, preview production-сборки:
<http://127.0.0.1:4173>. Эти standalone-серверы не проксируют API: для
работающего каталога используйте Compose с backend и миграциями.
`build` включает typecheck. Vitest + jsdom + Testing Library проверяют UI
и границы адаптеров; версии закреплены в `package.json` и lockfile.
GitHub Actions запускает `npm --prefix frontend test` вместе с прежними
проверками типов, сборки, backend, Compose и PostgreSQL.

Из корня репозитория для сквозной проверки:

```sh
cp .env.example .env
make init-secrets config build
npm --prefix frontend ci
cd frontend && npx playwright install --with-deps chromium && cd ..
make catalog-browser-smoke
```

Runner создаёт уникальный Compose-проект и временные секреты, применяет
миграции, маркирует только свою новую БД и запускает существующий guarded
demo seed. Обычный demo volume не используется. После проверки удаляются
только volumes этого проекта. `CHROMIUM_EXECUTABLE=/usr/bin/chromium`
позволяет явно использовать установленный системный Chromium.

## Работа интерфейса

- Поиск по названию/SKU отправляется кнопкой «Найти» или Enter. Доступны
  фильтры product/service и модели, сброс, пагинация по 20 позиций.
- Фильтр модели оставляет только публично подтверждённые позиции. Открытая
  карточка сохраняет контекст модели и показывает `confirmed` или `unknown`;
  unknown не означает несовместимость. Без модели applicability = null.
- Список использует `CatalogCard`; описание загружается отдельным HTTP
  запросом как `CatalogItem`. До MVP-024 фильтр модели честно возвращает
  пустой список: подтверждённых связей в БД ещё нет.
- Изображение берётся только с разрешённого same-origin пути своей позиции.
  При null, небезопасном URL или ошибке загрузки — заглушка. До MVP-025
  backend всегда возвращает image_url=null.
- Добавление одной позиции повторно отключено. Общий список сохраняется
  при фильтрах и переходе в карточку. Количество — целое 1–999; удаление явно.
  Защитный лимит списка — 100 позиций.
- Цены остаются decimal-строками. Расчёт известной части выполняется через
  целочисленные копейки (`bigint`), без округления через `Number`.
  `on_request` и недоступные позиции не превращаются в нулевую цену.
  Доставка и окончательная стоимость не обещаются.
- Loading, empty, ошибки списка/моделей/карточки/выбранного имеют отдельное
  отображение и повтор загрузки. Устаревшие async-ответы игнорируются.

## Данные и подключение API

`src/api/catalog.ts` задаёт интерфейс источника. В `src/App.tsx` явно выбран
`httpCatalog`. `fixtureCatalog` доступен только изолированным тестам; runtime
его не импортирует и не переключается на него при сбое.

`httpCatalog` выполняет same-origin GET:

- `/api/v1/equipment-models?limit=100&offset=…` (все страницы моделей);
- `/api/v1/catalog/items?q=…&kind=…&model_id=…&limit=…&offset=…`;
- `/api/v1/catalog/items/{id}?model_id=…`.

Он передаёт AbortSignal, кодирует query-параметры, отклоняет HTTP-ошибки,
невалидный JSON и некорректную минимальную форму ответа. Автоматической
подмены API fixtures нет. Generated `types.ts`, `fixtures.ts` и `fixtures.json`
не изменены; авторитетные бизнес-ограничения остаются в backend-контрактах.

В sessionStorage под ключом `akbrizcase.selected-items` хранится только массив
`{item_id, qty, revision}`. При восстановлении лишние поля удаляются,
дубликаты/невалидные строки отбрасываются. Данные и цены повторно получаются
из текущего источника по ID. Изменившаяся revision отмечается в UI;
сохранённая revision не подменяется молча. Недоступную позицию можно удалить
или загрузить повторно. При блокировке storage список работает в памяти
и показывает предупреждение. LocalStorage не используется.

Контакты, комментарии, чаты и клиентские цены не сохраняются в browser storage.
При подтверждении только временные Idempotency-Key и X-Request-Token хранятся
в sessionStorage до успеха или явно безопасного повторного обзора. Строки отображляются
React как текст, без raw HTML. Секреты и `.env` не нужны: всё в bundle и
`VITE_*` публично, чувствительные значения туда помещать нельзя.

## Живая заявка

Форма использует тот же выбранный список. При входе перечитывает позиции из API,
показывает товары/услуги, количества, актуальные цены, известную часть суммы,
неизвестные цены и доставку. Лимит заявки — 50 уникальных позиций (список каталога
сохраняет лимит 100): превышение блокирует отправку без обрезания. Изменившуюся
revision нужно принять отдельной кнопкой; недоступную позицию — удалить в каталоге.

Контактное имя обязательно (≤200), email (≤254) и/или телефон (≤32, 7–15 цифр),
организация (≤200), город при доставке (≤200), комментарий (≤2000). Непустые строки
отправляются точно как введены. Backend остаётся авторитетом валидации.
`httpOrders` загружает полный действующий текст/цель/версию через
GET `/api/v1/consent-text`; нужны отдельные явные согласие и подтверждение.
Синтетический demo-текст не утверждён юридически: реальные ПДн вводить нельзя.

POST `/api/v1/orders` отправляет `source=site`, без `chat_session_id`, цен и статусов.
Web Crypto создаёт UUID и независимый 256-битный lowercase-hex токен. Контроллер
блокирует двойной клик до fetch. Только пара заголовков сохраняется под
`akbrizcase.pending-order`; точный JSON с контактами остаётся в памяти.
После таймаута/сбоя/503 кнопка «Повторить отправку» использует исходные тело,
ключ и токен. 201 и 200 показывают один и тот же исходный безопасный receipt;
после успеха pending-секреты удаляются.

409 каталога/согласия перечитывает данные; только явный повторный обзор, свежее
согласие и подтверждение позволяют создать новую пару. 422 сохраняет поля для
исправления через явный обзор. 404 и IDEMPOTENCY_CONFLICT блокируют новую отправку
и направляют к менеджеру без раскрытия причины скрытия объекта.

После reload при unresolved marker исходное тело с ПДн потеряно: UI сообщает
неопределённость и блокирует восстановление/новую отправку. Сначала нужно
уточнить результат у менеджера, иначе возможен дубликат. Возврат в каталог в
той же открытой странице сохраняет форму и исходный payload для безопасного повтора.
Токены не попадают в URL, DOM, историю или логи; localStorage не используется.

Для реальной приёмки с доверенным HTTPS, PostgreSQL 16, потерянным ответом после
commit, точным retry, конфликтами и чтением manager без SMTP:

```sh
make local-tls # один раз, если .certs ещё нет
make request-browser-smoke
```

Команда включена в Compose CI job, использует только собственную одноразовую
маркированную synthetic БД и не пишет HAR/trace/скриншоты с контактами или токенами.
Подробные границы и результаты — в [MVP-013](../docs/MVP-013.md).
