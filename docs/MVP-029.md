# MVP-029 — схема чат-сессий и сообщений

База: `origin/main`, `a9cdde597840c6758d469fc726105bc5cd41d073`.
Объём: IMPLEMENTATION_PLAN.md MVP-029, ARCHITECTURE.md §§4.4, 5.4–5.5, 5.7.

## Хранение

Единственная новая Alembic revision `0007_mvp029_chat` следует непосредственно
за `0006_mvp027_diagnostic_trees`. Upgrade добавляет две таблицы, nullable FK
и индекс `orders.chat_session_id`. Существующие заявки не переписываются.
CHECK `orders.source` теперь допускает `site/chat`; HTTP orders по-прежнему
отклоняет source=chat до реализации проверки владения в MVP-036.
Обязательный support.comment и остальные ограничения orders сохранены.
Downgrade с потерей истории запрещён по принятой в репозитории конвенции.

`chat_sessions`: UUID v4 PK, обязательный owner_token_hash (64 lowercase hex),
mode diagnose/knowledge/commerce, nullable tree_id/current_node_key/outcome,
state_version >= 0 (по умолчанию 0). Хранится только хэш; UUID сессии остаётся
идентификатором, не доказательством владения. Выдача/проверка токенов сюда не входит.
FK tree_id указывает на UUID конкретной версии diag_trees с RESTRICT, а не на
логический key. Ссылка на дерево возможна в diagnose; ключ узла требует дерева
и использует формат ключей MVP-027. Проверка существования узла в графе и
доступности опубликованного дерева остаётся обязанностью будущего сервиса.
Outcome допускает только resolved/handoff/unresolved либо NULL; условия фиксации
resolved по кнопке также относятся к будущему runtime.

Время — timestamptz, соединения приложения используют UTC. Серверные defaults:
created_at/last_activity_at=now(), expires_at=now()+24 hours. CHECK требует конечные
метки, created_at <= last_activity_at <= expires_at и срок ровно 24 часа от создания.
Индексы: expires_at, tree_id.

`chat_messages`: UUID v4 PK, session_id FK с CASCADE, request_id UUID,
обязательный request_hash (64 lowercase hex), input/response как JSONB object,
state_version_after > 0, matched_by button/keyword/search/none, latency_ms >= 0,
конечный created_at timestamptz с серверным now(). UNIQUE(session_id,request_id)
обеспечивает конкуренцию на уровне БД; отдельный индекс (session_id,created_at)
поддерживает чтение истории. Одна строка хранит полный обмен запрос/ответ.

Обновление состояния и обмена одной транзакцией поддерживается существующим UoW.
Проверка owner, SELECT FOR UPDATE сессии, replay по хэшу и expected_version,
увеличение версии и актуальная проверка источников будут реализованы следующими
MVP. Наличие полей/UNIQUE само по себе не реализует этот runtime-протокол.
Фильтрация входного текста до записи и безопасная проекция response также не
подменяются JSONB CHECK: здесь нет принимающего текст API.

## Приёмка

Локально выполнены на PostgreSQL 16.13:

- `python scripts/db_integration.py --suite clean-upgrade` — чистый upgrade,
  повторный upgrade и совпадение таблиц с ORM metadata;
- `python scripts/db_integration.py --suite chat` — 56 проверок, включая реальные
  CHECK/NOT NULL/FK/UNIQUE, UUID/UTC/JSONB, привязку к версии дерева, два
  конкурентных INSERT с одинаковым request_id и с разными request_id,
  rollback состояния и сообщения при ошибке;
- удаление сессии через SQL проверяет CASCADE сообщений, сохранность другой
  сессии и SET NULL связанных commercial/support-заявок. Полные строки orders
  сравниваются с изменением только chat_session_id, остальные строки снимков,
  consent/text, истории, outbox и каталога — без изменений. Менеджерский read
  получает прежний comment. CHECK описания действует после удаления чата;
  прежнее исключение при законном pii_erased_at продолжает работать;
- upgrade заполненной схемы проходит через 0006: прежние commercial/support,
  снимки, consent, история, outbox, staff и каталог сравниваются до/после.
  Определения функций и триггеров деревьев также сравниваются без изменений;
- backend: 622 теста, Ruff check/format и strict Mypy.

Первый локальный core-run: 751 passed, 1 failed, 1 skipped. Отказ — прежняя
проверка отсутствия chat_session_id; заменена на точную проверку nullable UUID.
После исправления она и весь chat-suite выполнены вместе: 57 passed.
Первый Compose CI также выявил устаревший явный список таблиц; в него добавлены
обе chat-таблицы. Полные CI jobs повторяются на окончательном HEAD после этих
адаптаций; проверки ограничений, снимков и outbox не отключены.

Адресный suite `chat` включён в общие `make integration` и `make integration-ci`
в рамках прежнего ограничения двух параллельных тестовых стеков. Старые suites
сохраняются. В managed cloud локальный запуск использует временный CA-only
`DB_TEST_BUILD_OVERRIDE` и writable `BUILDX_CONFIG`/`UV_CACHE_DIR` вне git;
проверка TLS включена. Тестовые volumes сохранены.

Четыре обязательных полных CI jobs выполняются на итоговом HEAD отдельного PR:
Backend checks, Frontend checks, PostgreSQL 16 integration, Compose build and smoke.
Их фактические результаты и итоговый SHA приводятся в отчёте PR/задачи.
