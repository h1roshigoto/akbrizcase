# MVP-027 — диагностические YAML-черновики

База: `56fe608549a47317244986df863b31e745a7efe0` (`origin/main`).
Ветка: `mvp-027-diagnostic-trees`. Только синтетические данные.
Импорт создаёт исключительно `draft`; успешная техническая проверка никогда
не означает экспертного утверждения или разрешения публичной диагностики.

## Строгий входной формат

`content/trees/valid/` содержит примеры с placeholder UUID, `invalid/` — отказы.
Схема определена Pydantic-моделями в `kb/tree_schema.py`, extra=forbid,
strict=true, без преобразования строк/boolean в числа. Обязательны ровно:

```yaml
# SYNTHETIC ONLY: no manufacturer instructions or expert approval.
key: SYNTHETIC-027
version: 1
model_code: SYNTHETIC-MODEL
title: SYNTHETIC ONLY
start: specialist
nodes:
  specialist:
    type: handoff
    text: 'SYNTHETIC ONLY: contact a specialist.'
    risk: expert_only
```

key, model_code, node_key, option.id/next: 1–100 ASCII знаков,
`[A-Za-z0-9][A-Za-z0-9_.-]{0,99}`. Version: integer 1…2147483647.
Title: 1–200 знаков, непустой, без крайних пробелов и управляющих символов.
Nodes — непустой mapping до 200 узлов. Node имеет обязательные type/text/risk:

| Поле | Правило |
|---|---|
| type | Только question/result/handoff |
| text | Непустой plain text, максимум 4000 знаков |
| risk | Только observation/expert_only; expert_only только handoff |
| source_refs | До 20 уникальных канонических ненулевых UUID разделов |
| options | Только question; 2–10 объектов с ровно id, text, next |
| recommendations | Только result; до 20 объектов с ровно item_id, qty |

Все question/result требуют хотя бы одного источника (консервативное правило
§3.3, без автоматического определения «нетехнических» вопросов).
Handoff может не иметь источников. Result/handoff не допускают даже пустого
options. Question/handoff не допускают recommendations. ID опций уникальны
в узле; повторные source_refs/item_id в одном узле запрещены. UUID источника
однозначно определяет document_version/document: входных document_id/version_id
рядом нет. Рекомендация использует существующий UUID товара **или услуги**;
qty — целое 1…999, boolean/float/строки запрещены. Никаких actions, shell,
HTML, JavaScript, Python-конструкторов, внешних URL/файлов и полей actor/status/
approval/publication. Базовый JSON Schema: `TreeInput.model_json_schema()`;
межполевые правила дополняют Node validators и `validate_graph()`.

## YAML и граф

PyYAML 6.0.3 закреплён вместе с types-PyYAML в uv.lock; прежние зависимости
не обновлены. Используются только parser events SafeLoader: construct/load
и пользовательские конструкторы вообще не вызываются. Явные tags (даже !!str),
anchors, aliases, merge keys, сложные ключи, directives и несколько документов
отвергаются. Дубли mapping keys проверяются на каждой глубине до построения DTO.
Максимум 262144 байта, 12000 событий, глубина 12, scalar 4000 знаков.
UTF-8 strict, NFC без тихой нормализации; BOM, bidi/zero-width/control chars
запрещены, LF/TAB допустимы в многострочном plain text. YAML-даты/float не
преобразуются в объекты; plain true/false/null и десятичные integers имеют
минимальную явную семантику. Ошибки содержат фиксированные коды, проверенный
node_key/имя поля; parser snippets и сырые Pydantic errors не выводятся.

Reachability — итеративный обход от start. Затем Kahn topological sort по всем
узлам обнаруживает и недостижимые циклы. Все next должны существовать; ни одного
недостижимого узла. В ацикличном графе каждый question имеет ≥2 ребра,
а листья только result/handoff, поэтому каждый путь терминален. По
топологическому порядку считается самый длинный путь; больше 30 рёбер — PATH_LIMIT.
Это валидация O(V+E), runtime step/чат/счётчик переходов не реализованы.

Консервативные текстовые deny-эвристики обнаруживают URL/code/HTML и ряд русских/
английских опасных формулировок. Они не доказывают безопасность текста и не
заменяют человека. Ни один импорт не выставляет expert_name, review_reference,
approved_at, published_by или published_at; отчёт всегда expert_approval=false
и содержит EXPERT_REVIEW_REQUIRED.

## Схема и история

Одна линейная revision: `0006_mvp027_diagnostic_trees` после
`0005_mvp024_applicability`. SCHEMA_REVISION и регистрация metadata обновлены.
Upgrade только добавляет три таблицы, индексы и invoker-rights triggers с
фиксированным search_path; прежние данные/объекты не переписывает.

diag_trees: UUID PK, UNIQUE(key,version), положительная version, строгие
key/title/checksum/git_commit/status, JSONB object graph, model FK.
Частичный UNIQUE(key) WHERE published; индексы (model_id,status,key),
(status,key), UNIQUE(key,version). SHA-256 — 64 lowercase hex. Git commit —
полный 40/64 lowercase hex, переданный оператором как происхождение файла.
Проверка наличия этого файла в remote Git не выполняется; разрешение публикации
из commit не выводится.

diag_tree_sources: PK(tree_id,node_key,section_id), FK section_id; индекс
section_id. diag_tree_items: PK(tree_id,node_key,item_id), FK item_id, qty
CHECK 1…999; индекс item_id. Все FK, включая model/publisher/tree, RESTRICT.
В graph только start/nodes/тексты/risk/options, без source_refs/recommendations.
При check граф собирается с нормализованными связями и вновь валидируется.
Неизвестный node_key связи, встроенные source_refs/recommendations в JSON и
расхождение сохранённого содержимого с import audit отвергаются.

У draft все approval/publication поля NULL. Published/retired требуют полный
набор корректных реквизитов, конечные timestamps и approved_at ≤ published_at.
Revoked допускает пустой набор (отозванный draft) или полный неизменяемый набор.
Идентичность id/key/version/model неизменяема; один model_id для всех версий key
защищён также insert-trigger с advisory lock. Содержимое, связи и согласования
published/retired/revoked неизменяемы. Удаление исторической версии, возврат
в draft и восстановление revoked запрещены. Triggers не заменяют будущий
publication validator. Приложение не имеет lifecycle/CRUD обхода.

## Команды и транзакции

В Python 3.12 среде с настроенным runtime DB и защищённым терминалом:

```sh
cd backend
uv run --locked python -m app.modules.kb.cli tree-check --file /operator/synthetic.yaml
uv run --locked python -m app.modules.kb.cli tree-import --file /operator/synthetic.yaml --git-commit FULL_COMMIT_SHA
uv run --locked python -m app.modules.kb.cli tree-check --tree TREE_UUID
```

Можно использовать существующий Compose kb с read-only operator mount из
compose.kb.yml. Сканер/ClamAV для YAML не вызывается: нет бинарного файла,
выполняемого кода, внешних ссылок или object deserialization. Существующий
конвейер документов и изображений сохранён.

Login/password вводятся скрыто общим hidden/getpass. authenticate_operator
использует настоящий Argon2id и commit-scoped lock_staff; active admin обязателен
даже для check. Manager/disabled/anonymous получают безопасный отказ **до чтения
файла**. Нет --actor-id/--password/--publish/--skip-validation и публичного HTTP.
Неизвестные аргументы отвергаются без эха. Результат CLI печатается только после
outer UoW commit; SQL/audit/commit errors — OPERATION_FAILED_ROLLED_BACK, exit 1.

Файл читается bounded через существующий operator_file: regular file,
O_NOFOLLOW/O_NONBLOCK, одна hardlink; никакого сетевого/внешнего чтения. До выхода
из savepoint повторно проверяются inode и все байты исходного/повторно открытого
descriptor. Подмена даёт YAML_CHANGED с откатом успешной записи и audit.
SHA-256 считается по точным UTF-8 байтам, включая комментарии и пробелы.

Повтор key/version/checksum сверяет graph/title/model и обе группы связей с
оригинальным неизменяемым import audit, возвращает NO_OP без перезаписи UUID,
git provenance или approval. Другие байты — CHECKSUM_CONFLICT. Другая model
у key — MODEL_CONFLICT. Новая version — новый draft. Исправление — новый файл
с новым номером версии; generic CRUD и неявное исправление draft отсутствуют.
NO_OP исторической версии также ничего не меняет; tree-check --tree проверяет
именно draft.

Audit содержит настоящего actor, UTC, tree UUID, tree.import/tree.check,
result, коды препятствий и SHA-256 binding, без YAML/текста/заголовков/паролей/
путей. Binding: canonical JSON UTF-8, sort_keys, ensure_ascii=false, компактные
separators; format=diag-import-v1, key/version/model_id/title/graph,
yaml_checksum/git_commit и отсортированные source/item tuples. Check сохранённого
draft сверяет binding с первоначальным IMPORTED_DRAFT audit. Исходные байты
в БД не сохраняются: для независимой сверки yaml_checksum повторить импорт
исходного файла; совпадающие данные дадут NO_OP. SHA-256 не является подписью.

## Основания и блокировки

Структурные отказы (MODEL/SOURCE/ITEM_NOT_FOUND, GRAPH/SCHEMA_INVALID) отличаются
от текущих publication_blockers. Непубличный/отозванный/retired/неразрешённый
источник может храниться у draft, но SOURCE_NOT_PUBLIC явно запрещает считать
его готовым к публикации. Проверка использует существующий
accessible_version(PUBLIC_VIEWER), published-only, и assistant_allowed.
Применимость товара/услуги проверяется **единственным** confirmed_evidence(model_id)
MVP-024; unknown/candidate/устаревшее evidence даёт APPLICABILITY_NOT_CONFIRMED.
Internal evidence применимости может подтверждать факт по MVP-024; это не
открывает internal source_refs дерева. Непубличная модель — MODEL_NOT_PUBLIC.
Изменение ACL/status никогда не публикует draft.

Порядок: существующий staff lock → advisory по diag-tree:key → documents по UUID
→ versions по UUID → model → catalog_items по UUID → applicability по pair
→ версии дерева/связи. Никакой новой глобальной tree-блокировки. Существующий
глобальный staff lock сохраняет договор авторизации и может сериализовать CLI.
Предварительные probes выбирают parents, включая evidence рекомендаций;
после locks привязки перечитываются. При замене/удалении во время ожидания —
DEPENDENCIES_CHANGED: новая транзакция/повтор, без следования назад по lock order.
Section writers уже блокируют parent version; обратного section row lock нет.
Два импорта key/version сериализованы, одна запись + NO_OP; версии одного key
не расходятся по модели. Triggers связей блокируют tree parent, исключая гонку
с будущей публикацией. Timeouts DB/HTTP/AV не увеличены.

Все записи дерева/связей/success audit внутри одного savepoint и outer UoW.
Ожидаемый отказ откатывает savepoint и пишет denial audit; audit/DB/commit failure
пробрасывается и откатывает всю транзакцию. Никакого полуграфа или успешного
сообщения до commit. Ни документы, каталог, orders/consents/outbox не меняются.
