# MVP-035 — Публичный интерфейс чата

База: `89d7da30b7407e77ef7797682835ac8ec50b9303`, актуальный `origin/main`
при начале работы, совпадает с заданием. Ветка `mvp-035-chat-frontend`.
Миграции, таблицы, `ModeRouter`, атомарный writer и `ChatReplyProjector`
не изменены. Merge, deployment и MVP-036 не выполняются.

## HTTP-контракт сценариев

`GET /api/v1/chat/scenarios?model_id=<UUID>` — публичное чтение без cookie/token.
Ответ 200: `{"items":[{"key":"approved_code","title":"Название","model_id":"UUID"}]}`.
Явные DTO `ChatScenario` / `ChatScenarios`, максимум 10 после проверки ACL.
Адаптер вызывает существующий `published_scenarios()` / `load_tree()` с
`PUBLIC_VIEWER` внутри обычного UoW и согласованного снимка чтения.
Неизвестная/непубличная модель, отсутствие разрешённых деревьев или зависимостей
дают `{"items":[]}`. Граф, pin, узлы, переходы, документы и review не выдаются.
Staff-cookie не расширяет доступ. Некорректный/отсутствующий UUID — 422,
отказ БД — 503; штатный `ErrorEnvelope`, `Cache-Control: no-store` сохранены.
DTO включены в генератор TypeScript; `types.ts` сгенерирован, не исправлен вручную.

Список не является разрешением на будущий старт: каждый новый выбор модели и
«Обновить сценарии» выполняют GET. POST отправляет прежний `start_diagnosis`
с `model_id` и `tree_key`. Backend снова выбирает опубликованную версию.
Исчезнувшее дерево даёт безопасный handoff. Клиент не знает графа/SQL/ACL.

## Пользовательский поток

Каталог → «Помощник» → создание сессии или авторизованный GET восстановления.
Каталог сам не создаёт чат и не выполняет chat-запросы. `#chat` позволяет
перезагрузить открытый чат; URL не содержит owner token или пользовательский ввод.
Лёгкая навигация сохраняет выбор товаров, состояние каталога и коммерческую форму.
Активная страница — одно состояние catalog/chat/request, синхронизированное с hash
при hashchange/popstate и явных переходах. Back/Forward и повторное открытие чата
не оставляют скрытую форму активной. Возврат из формы меняет hash на #catalog;
форма остаётся смонтированной после первого открытия и сохраняет введённое в памяти.

Три режима переключаются только через POST `select_mode`; активная кнопка
отражает ответ сервера. UI сообщает о сбросе прогресса при фактической смене
режима и сохранении при повторном выборе. Диагностика: публичная модель →
разрешённый сценарий по названию → только актуальные серверные buttons →
результат/feedback. Выбор другой модели обновляет меню, а закреплённый путь
заменяется только явным стартом. В диагностике нет выбора перехода свободным
текстом. Knowledge/commerce принимают непустой trim и до 1000 символов.
Есть loading/empty/error, no_match, question/results/completed и видимый handoff,
labels, клавиатурные controls, мобильная вёрстка и постоянное предупреждение о ПДн.

## Хранение и повтор

`sessionStorage['akbrizcase.chat.v1']` содержит только `session_id`,
`session_token`, `expires_at`, `pending` (null или одно точное ограниченное
JSON-тело сообщения). История, цитаты, карточки, контакты и actions не сохраняются.
`localStorage` чат не использует. Обычное выбранное хранится прежним способом:
только item_id/qty/revision. Недоступное/повреждённое хранилище или ошибка записи
показывают предупреждение: восстановление после reload не гарантируется.

Контроллер живёт выше mount/unmount страницы, сериализует GET/POST и блокирует
двойные клики. StrictMode делит незавершённое открытие, не создаёт вторую сессию.
Каждый новый ввод получает `crypto.randomUUID()` и подтверждённую версию.
Точное сериализованное тело сохраняется до POST. Network/timeout/503 и
некорректный success считаются неопределённостью: пользователь явно повторяет
те же байты с прежними request_id/expected_version/input, включая после reload.
Новый логический ввод заблокирован до разрешения pending. Успех/окончательный
отказ очищают pending. Replay заменяет обмен по message_id; старая версия
replay не откатывает более новый GET и требует перечитывания.

`STATE_CONFLICT` очищает pending и все отображавшиеся технические ответы,
сообщает о конфликте и вызывает GET. `details.current_version` не используется,
старая кнопка автоматически не повторяется. `IDEMPOTENCY_CONFLICT` отдельно
показывает отказ и предлагает перечитать сессию, без нового автоматического POST.
404 и собственный 410 удаляют owner/pending, прекращают старую сессию и требуют
явного нового старта. Старый ввод в новую сессию не переносится. Срок 24 часа
фиксирован сервером, активность не продлевает его. Ошибка GET скрывает прежние
технические ответы и оставляет возможность перечитать, без fixture fallback.

GET восстановления/обновления заменяет историю целиком. «Предыдущие ответы»
перечитывает сначала уже показанные страницы и затем следующую, по `next_before`,
до 50 обменов за страницу. При concurrent смене версии история перечитывается
заново. В памяти объединение только по message_id и сортировка по state_version.
Пользовательский текст из истории не выдумывается: контракт содержит ответы.
Интерактивен только текущий reply после синхронизации; исторические кнопки/actions
не отображаются. Возврат в чат не показывает старый reply до GET.

## Источники и actions

React отображает строки как текст, CSS сохраняет переносы. HTML/Markdown parser,
`dangerouslySetInnerHTML` и выполнение команд из текста отсутствуют. SourceRef
показывает title/section/pages и ссылку только при точном совпадении с
`/api/v1/documents/{document_id}/versions/{document_version_id}/file`.
Новая вкладка имеет `noopener noreferrer`; отметка прошлой редакции — из title.
Изображения, цены, revision и applicability используют прежние компоненты каталога.
Null/unknown никогда не становится confirmed по выбранной в браузере модели.

Allowlist: open_item перечитывает публичную карточку перед навигацией;
open_document открывает точную безопасную версию; коммерческий open_request_form
перечитывает каждую предлагаемую позицию, проверяет qty/дубликаты и максимум
50 позиций в объединённом списке заявки, затем открывает
существующую форму для проверки пользователем. Уже выбранные позиции сохраняют
количество и исходную revision, чтобы форма могла показать изменения; новые
получают текущие revision. Обычный каталог по-прежнему сохраняет до 100 выбранных
позиций, но chat action не переводит к форме, если объединённый список больше 50.
Проверка и изменение списка выполняются синхронно относительно текущего значения,
включая устаревшие callbacks после HTTP и несколько изменений в одном React batch.
При отказе список не меняется частично. RequestPage использует тот же лимит 50
и независимо перепроверяет каталог/цены.
Ни одно chat action не вызывает POST orders. Недоступная позиция оставляет
понятный отказ без частичной заявки. Support/contact_specialist честно сообщают,
что оформление по результатам диагностики относится к MVP-036; отправки нет.
Черновики comment_draft, копирование переписки и support confirmation не добавлены.

## Проверка и ограничения

Новые backend unit проверяют DTO/OpenAPI, 422/503/no-store/UoW, явную проекцию
и limit после loader. PostgreSQL проверяет реальный HTTP-старт/переход, исчезновение
меню до старта, unpublished/unknown models, draft/retired/revoked, source ACL,
staff-cookie, версии одного ключа, лимит после ACL, отсутствие DML и corrupt graph.
Прежние MVP-033/034 security/concurrency тесты сохранены.

Frontend unit/component проверяют owner/reload, все режимы, диагностические
buttons/feedback, knowledge/no_match, commerce/unknown, SourceRef/XSS, actions,
отсутствие POST orders, точный retry/replay, конфликты, expiry/404/503, storage,
пагинацию/revocation и StrictMode/навигацию. Только синтетические данные.

`make chat-browser-smoke` запускает отдельный `SyntheticStack`: уникальный Compose
project, маркированные volumes/БД, штатные migrations/seed и службы публикации.
Fixture создаёт модель через CatalogWriteService, файл через FilePipeline +
реальный clamscan с синтетической подписью (как существующая file acceptance),
документ/сценарий через draft/review/publish и проверки evidence. Production CVD,
ACL, file validation и publish validators не изменяются. Chromium проходит
React → Nginx → FastAPI → PostgreSQL без route mocks: knowledge + exact file href,
commerce + публичная карточка, diagnose + реальный переход/feedback, reload,
отсутствие orders/localStorage и мобильного overflow. Секреты и тела запросов
не выводятся, traces/screenshots/HAR не создаются. Volumes сохраняются.
Проверяется точный href, а не скачивание файла: production file endpoint по-прежнему
требует операторские свежие подписанные CVD, не синтетическую тестовую подпись.
Smoke включён в существующий Compose CI job; четыре jobs сохранены.

Между серверными запросами уже показанный контент нельзя отозвать мгновенно:
обновление/возврат/история получают новую безопасную проекцию. Пагинация требует
дополнительных GET для повторной проверки показанных страниц и использует отдельные
серверные снимки; при конкурентном отзыве следующее чтение увидит его.
Отдельные browser traces отсутствуют намеренно. LLM/RAG, внешние AI API,
WebSocket/streaming, deployment и новый backend движок не добавлены.
MVP-039 остаётся самостоятельным условием публичного production-запуска;
этот PR не означает готовность всего портала к production.

предлагаемых позиций через каталог и проверка всей заявки в RequestPage сохранены.

чата, сохранение выбранного и введённого в форму. Общая настройка тестов сбрасывает
URL между тестами, чтобы #request предыдущего теста не менял старт следующего.
