## Workflow и локальные команды

`.github/workflows/ci.yml` запускается на каждом `pull_request` в `main`
и `push` в `main`, без фильтра по файлам. Три независимые job на
`ubuntu-24.04` используют те же команды, что разработчик из корня:

| Job | Подготовка | Проверки |
|---|---|---|
| `backend` | Python 3.12.14; pip устанавливает uv 0.12.23; `make backend-sync` → `uv sync --locked` | `make backend-test backend-lint backend-types`: pytest, Ruff check/format --check, mypy strict |
| `frontend` | Node.js 24.19.0; npm 11.9.0; `make frontend-sync` → `npm ci` | `make frontend-typecheck frontend-build`: tsc --noEmit и Vite build |
| `compose` | Python 3.12.14; `cp .env.example .env`; `make init-secrets` | `make config`, `make build`, полный `make smoke` |

Версии Python/uv/Node/npm проверяются явно. Backend использует
`backend/uv.lock`, frontend — `frontend/package-lock.json`. `uv run --locked`
не обновляет lockfile; mypy strict уже включён в backend/pyproject.toml.
Dockerfile сохраняют зафиксированные версии и locked/npm ci установку.

Общие команды:

```sh
make backend-sync frontend-sync
make lint   # Ruff check/format + frontend typecheck
make types  # mypy strict + frontend typecheck
make test   # pytest + frontend build (включает typecheck)
```

Frontend unit suite пока отсутствует: `make test` использует существующий
build, а `make lint` — существующую проверку типов. Новый линтер или тестовый
раннер не добавляются. Команды Compose MVP-055 и прежняя default-цель
`init-secrets` сохранены.

Полный smoke включён: стандартный Linux runner предоставляет Docker/Compose
и loopback. Проверяются Nginx UI/assets/health/API proxy, общий образ API/worker,
внутренний PostgreSQL 16 и парольная аутентификация, отсутствие публичных
DB/API/worker портов, закрытый файловый volume, штатная остановка и сохранение
синтетических маркеров после down/up. Smoke удаляет только свой уникальный
проект/volumes в `finally`. Это проверка существующей инфраструктуры MVP-055;
интеграционный контур приложения с драйвером БД/миграциями остаётся MVP-003.

## Безопасность и остановка при ошибке

- Только `permissions: contents: read`, checkout без сохранения credentials.
- Actions checkout/setup-python/setup-node закреплены полными commit SHA;
  соответствие тегам v6 проверено через GitHub API при реализации.
- Нет `pull_request_target`, GitHub secrets, SMTP, сервера, deploy или push
  образов. Job не публикуют артефакты или данные.
- `make init-secrets` создаёт случайный синтетический пароль в защищённом
  файле; значение не печатается и не передаётся через build args/env.
  `.env`/`.secrets` исключены из Git; Docker-контексты используют allowlist.
  В `always()` удаляются временные `.env` и `.secrets`.
- TLS-проверка не отключается. Установка npm явно использует strict SSL.
- Bash в Actions выполняется с `-e -o pipefail`; Make передаёт ошибки
  вложенных команд. Нет `continue-on-error`, игнорирования exit code или
  условного пропуска smoke. Только удаление временного пароля выполняется
  после ошибки; оно не превращает упавшую job в успешную.
- Таймауты: backend/frontend 10 минут, Compose 20 минут.

## Definition of Done и границы

- Проверки чистого clone заданы в workflow через общие локальные команды;
  установка строго из существующих lockfiles.
- Ошибки тестов/типизации/сборки останавливают команду с ненулевым кодом;
  негативные проверки выполнены локально в оболочке с флагами Actions.
- Production-секреты и реальные данные не используются; runtime-пароль
  отсутствует в Git и контекстах сборки, не печатается командами.
- Фактический статус GitHub Actions и контейнерного smoke указан в PR.
  До успешного GitHub run CI считается неподтверждённым.

Бизнес-функции, миграции, content checks, release/deploy (MVP-041) и публикация
образов не добавлены. Автоматический merge не выполняется. Событие push в main
можно проверить только после отдельного одобренного merge; этот PR его не делает.
